# Case Study Intake Form

Collect real project data before publishing construction or recurring facility case studies. **Do not invent case studies.** Every published case study must have written client permission and verifiable details.

Related: [proof-ledger.md](../growth-playbook/proof-ledger.md), [completion-status.md](../growth-playbook/completion-status.md)

---

## Instructions for owner / sales / ops

1. Complete this form within 7 days of project completion or after 30 successful days on a new recurring account.
2. Obtain signed or emailed permission before any public use (website, GBP, LinkedIn, ads, proposals).
3. Send completed forms to marketing/web for draft review. Web does not publish without permission checkbox marked Yes.
4. Store signed permissions in a shared folder with the project name and date.

### Construction narrative prompts (for writer)

Answer in plain language. Do not embellish.

1. What problem was the GC or owner trying to solve before Imperial arrived?
2. What made the schedule difficult?
3. How were phases staged (rough, final, touch-up)?
4. What would have gone wrong without a dedicated cleanup crew?
5. What would you tell another GC about working with Imperial on this project?

## Minimum bar for publication

A case study may go live only when all of the following are true:

- [ ] Written permission for every element used (name, photos, quote)
- [ ] Facts cross-checked against job records (sq ft, dates, phases)
- [ ] No inflated metrics or competitor comparisons without source
- [ ] Claims added to [proof-ledger.md](../growth-playbook/proof-ledger.md) if new numbers are introduced
- [ ] Client quote matches what they actually said (no composite fake quotes)

---

## Storage

Save completed intakes as: `case-study-intake-{client-slug}-{YYYY-MM-DD}.md` or PDF in the owner shared drive. Do not commit client PII to the public git repo unless redacted.

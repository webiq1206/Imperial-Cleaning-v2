# Imperial Cleaning Inc — Construction Project Prospecting Pipeline (Admin Tool)

## Project Context

Imperial Cleaning Inc (imperialcleaninginc.com) is a commercial and construction cleaning company headquartered in Idaho Falls, serving Idaho and Utah. The business specializes in two core areas: post-construction cleanup (rough clean, light clean, final clean) and ongoing commercial janitorial services. The owner is Francisco.

The site is built with Next.js, TypeScript, and Supabase.

I need a construction project prospecting tool built into the admin panel at `/admin/projects` (or similar admin route). This tool helps Imperial Cleaning find active commercial construction projects that are approaching the cleanup phase, identify the decision makers (general contractors, project managers, construction managers), and manage outreach to win construction cleanup bids.

-----

## The Business Problem This Solves

Construction cleanup is won by timing. By the time a building is finished, the general contractor has already hired their cleanup crew — usually months before. Imperial needs to find projects while they’re still in the framing or drywall phase, reach out to the GC or project manager, get on the bid list, and submit a proposal before the job is awarded.

The construction cleanup sales cycle looks like this:

1. **Commercial building permit is pulled** (months before cleanup is needed)
1. **Project enters framing / rough-in phase** (Imperial should be making first contact here)
1. **Drywall is installed** (the sweet spot — rough clean is needed soon, and final clean is on the horizon)
1. **Interior finishes begin** (light clean / dust control phase)
1. **Final finishes complete** (final clean needed — if Imperial isn’t already contracted, it’s too late)
1. **Certificate of Occupancy** (building handed over)

Imperial needs to catch projects at stages 1-3. That’s where this tool comes in.

-----

## What This Tool Does

### Core Functions

1. **Construction Project Discovery** — Find active commercial construction projects across Idaho and Utah through multiple data sources: building permit databases, plan rooms, construction project databases, Google Maps (active construction sites), and manual entry from Francisco’s network.
1. **Project Database** — Store every project with building details, construction phase/timeline, general contractor info, project manager contacts, estimated cleanup scope, and bid status.
1. **GC & Contact Management** — Build a database of general contractors, construction companies, and project managers that Imperial works with or wants to work with. Track relationships across multiple projects.
1. **Bid Pipeline** — Track every project through the bid process: Discovered → Researching → Contacted GC → Plans Received → Bid Submitted → Awarded → Lost → Completed.
1. **Bid/Proposal Generator** — Generate branded PDF proposals and bid sheets for construction cleanup jobs with scope of work, phased pricing (rough, light, final), and timeline.
1. **Project Timeline Tracker** — Estimate when each project will need cleanup based on construction phase and permit dates, so Francisco can time outreach perfectly.
1. **Relationship Dashboard** — Track which GCs have given Imperial work before, which ones are active in the market, and which relationships need nurturing.

## Technical Requirements

### Stack

- **Frontend**: Next.js with TypeScript (matching the existing site)
- **Backend**: Next.js API routes
- **Database**: Supabase (PostgreSQL)
- **PDF Generation**: Server-side for bid proposals
- **Maps**: Google Maps for project location visualization
- **Styling**: Match the imperialcleaninginc.com aesthetic — professional, dark/navy tones, clean and corporate. The admin panel should feel like a serious business tool.

### API Keys (environment variables)

- `GOOGLE_MAPS_API_KEY` — For geocoding project addresses and map display
- `GOOGLE_PLACES_API_KEY` — For finding construction companies and GCs
- `CONSTRUCTIONWIRE_API_KEY` — BuildCentral API for construction project leads (primary data source)
- `CONSTRUCTION_MONITOR_API_KEY` — Construction Monitor API for building permit data
- `SHOVELS_API_KEY` — Shovels.ai API for permit and contractor intelligence
- `CONSTRUCT_A_LEAD_API_KEY` — Construct-A-Lead API for pre-bid project leads

## Feature Specifications

### 1. Construction Project Discovery — AUTOMATED DATA SOURCES

This is the most critical feature. The goal is to have new commercial construction projects automatically flowing into the pipeline with minimal manual effort. There are multiple data sources that can feed this system, and the tool should support all of them.

**TIER 1 — API-Based Automated Feeds (Primary Sources)**

**a) ConstructionWire / BuildCentral API (RECOMMENDED — HIGHEST PRIORITY)**
ConstructionWire (owned by BuildCentral) is the industry-standard database with 720,000+ commercial construction projects in planning, bidding, and pre-construction stages. They have a REST API called the BuildCentral API.

The tool should integrate with this API:

- API documentation is published on Postman: https://www.postman.com/buildcentral/public/documentation/gxn6y0g/constructionwire-api-2-0
- Filter projects by: location (Idaho, Utah), project type (commercial, medical, retail, apartment, hotel, warehouse, school, etc.), project value ($500K+), project stage (pre-construction, bidding, early construction)
- Pull: project name, address, project description, square footage, project value, stage, GC name, GC contact info, architect, owner/developer, key dates
- Set up automated daily or weekly sync to pull new projects matching our criteria
- Store the ConstructionWire project ID to avoid duplicates and enable updates
- Environment variable: `CONSTRUCTIONWIRE_API_KEY`

Francisco should sign up for ConstructionWire (they offer free trials) and get API access through the BuildCentral API program. Call 866-316-5300 to discuss API pricing.

This is the #1 data source. If only one integration gets built, it should be this one.

**b) Construction Monitor REST API (Building Permit Data)**
Construction Monitor aggregates building permit data from 70+ metro areas nationwide, updated daily. They have a REST API.

- Filter by: geography (Idaho Falls, Boise, Pocatello, Salt Lake City, Logan, etc.), permit type (commercial new construction), construction type, permit value
- Pull: permit number, address, project description, contractor name, owner name, permit date, project value, construction type, geocode data
- Permits are the earliest signal — a commercial building permit means construction is starting soon
- Environment variable: `CONSTRUCTION_MONITOR_API_KEY`
- Website: constructionmonitor.com/data

**c) Shovels.ai API (Building Permit Intelligence)**
Shovels provides a modern, developer-friendly API for building permit and contractor data. They cover residential and commercial.

- Filter by: geography, permit type (commercial), property type, status
- Pull: permit details, contractor information (including contact info), property data, inspection status
- The inspection status data is valuable — it can indicate what phase a project is in (foundation inspection passed = framing soon, framing inspection passed = drywall soon)
- Environment variable: `SHOVELS_API_KEY`
- Website: shovels.ai/api

**d) Construct-A-Lead API**
Another construction project database with API access focused on pre-bid projects.

- Provides project leads with GC contacts, materials lists, and bid stage info
- Supports daily automated data feeds
- Good for catching projects before they go to bid
- Environment variable: `CONSTRUCT_A_LEAD_API_KEY`

**TIER 2 — Scheduled Scraping / Monitoring**

**e) City Permit Portal Monitoring**
For Imperial’s primary markets, set up scheduled checks of public permit databases:

- **Idaho Falls**: eTRAKiT portal (trakit.idahofallsidaho.gov) — search for new commercial (COM) permits
- **Boise**: City of Boise PDS portal
- **Pocatello / Twin Falls / Other Idaho cities**: Various municipal portals
- **Utah cities**: Salt Lake City, Logan, Provo, Ogden permit portals

Build a scraper module that:

- Checks each portal on a configurable schedule (daily or weekly)
- Filters for commercial new construction permits over a configurable dollar threshold
- Extracts: permit number, address, description, contractor, owner, value, date
- Auto-creates project records in the database with source = “permit_database”
- Flags new permits on the dashboard for review

Note: Some portals may not be scrapeable. For those, provide a quick-add form to manually enter permit data found during weekly manual checks.

**f) Google Alerts / News Monitoring**
Set up automated monitoring for construction news:

- Scrape Google News or use Google Alerts webhook for terms like: “new construction Idaho Falls”, “commercial building permit Boise”, “groundbreaking ceremony Idaho”, “new development [city]”
- When articles are found, extract project details and create a prospect record for review
- This catches projects announced in local news before permits are even pulled

**TIER 3 — Manual Entry (Still Important)**

**g) Quick-Add from Field**
Francisco and his team still find projects by:

- Driving past construction sites
- Hearing about projects from GC contacts
- Plan room postings
- Chamber of commerce announcements

The mobile quick-add form is still essential (see original spec). These manual entries supplement the automated feeds.

**h) CSV / Bulk Import**
Support uploading a CSV of projects from any source (plan room exports, Dodge Data reports, etc.) with the same flexible column mapping from the webIQ pipeline.

**DISCOVERY DASHBOARD**

The discovery section of the admin should show:

**Automated Feed Status:**

- Connection status for each API (green = connected, yellow = needs attention, red = disconnected)

**New Projects Queue:**

**Discovery Settings:**

- Configure which data sources are active

- Set project type filters (which building types to include)
- Set minimum project value threshold

### 4. Bid Pipeline & Management

**Pipeline Board (Kanban):**
Stages:

1. **Discovered** — Project found, basic info entered
1. **Researching** — Gathering details: sqft, GC, timeline, scope
1. **GC Contacted** — Reached out to the general contractor
1. **Plans Requested** — Asked for plans/specs to bid
1. **Plans Received** — Have the plans, ready to estimate
1. **Estimating** — Working on the bid
1. **Bid Submitted** — Proposal sent to GC
1. **Bid Follow-Up** — Following up on submitted bid
1. **Awarded** — Won the job
1. **In Progress** — Actively performing cleanup
1. **Completed** — Job finished
1. **Lost** — Didn’t win (capture reason)
1. **Dormant** — Project stalled or delayed

- Drag and drop cards between stages
- Cards show: project name, building type, GC, estimated value, days in stage
- Stage transitions auto-log activities
- “Awarded” and “Completed” stages should update the GC’s revenue tracking

**Bid Calculator:**
When viewing a project, provide a built-in calculator:

- Input: building sqft, building type, cleanup phases needed
- Auto-pull pricing from the `cleanup_pricing` table
- Show: estimated hours, crew size, number of days, cost per phase
- Apply markup/margin
- Output: recommended bid price with breakdown
- Allow manual override of any number
- “Generate Proposal” button that takes this data into the PDF generator

## Data Source Integration Architecture

### How Automated Feeds Work

The system should use a cron-based sync architecture:

1. **Scheduled Jobs**: A background task runs on a configurable schedule (default: daily at 6 AM) for each active data source.
1. **Fetch & Filter**: The job calls the data source’s API with the configured geographic and project type filters.
1. **Normalize**: Incoming data is normalized into the standard project schema regardless of source format.
1. **Dedup Check**: Each incoming project is checked against existing records for duplicates.
1. **Queue**: New, non-duplicate projects go into a “Discovery Queue” for Francisco to review.
1. **Review**: Francisco reviews the queue, adds promising projects to the pipeline, dismisses irrelevant ones.
1. **Enrich**: For projects added to the pipeline, the system can auto-enrich by cross-referencing other data sources (e.g., a project found via permit data might get GC contact info from ConstructionWire).

### Data Source Settings Page (`/admin/projects/sources`)

For each data source, show:

- **Connection card**: Source name, logo/icon, connection status (connected/disconnected), API key status
- **Filters**: Geographic scope (which cities/counties), project types, minimum value, project stages
- **Schedule**: How often to sync (hourly, daily, weekly), last sync time, next scheduled sync
- **Stats**: Projects pulled (total, last 7 days, last 30 days), projects added to pipeline from this source
- **Test button**: Run a quick test query to verify the API connection and filters work
- **Sync Now button**: Trigger an immediate sync

### Source Priority & Enrichment

When the same project appears in multiple sources (common for large projects), the system should:

1. Link all source records to the single project
1. Use the richest data from each source (ConstructionWire for contacts, Construction Monitor for permit dates, Shovels for inspection status)
1. Show a “Sources” section on the project detail page listing where this project was found

## Important Implementation Notes

1. **Timing is everything.** The entire tool is oriented around catching projects at the right time. The timeline/reminder system is the most important feature after basic data entry. Francisco needs to know TODAY which projects are approaching the window where he should be calling the GC.
1. **The GC relationship is the real asset.** Projects come and go, but a good relationship with a GC means automatic invitations to bid on every project they build. The contractor directory should make it easy to nurture these relationships and track the lifetime value of each GC.
1. **The bid calculator saves hours.** Instead of manually estimating every job, the sqft × rate calculation gives a starting point that Francisco can adjust. The pre-populated pricing table is based on industry standards — he should update it with his actual experience over time.
1. **Mobile entry is critical.** Francisco drives past construction sites daily. He needs to capture a project in 30 seconds from his truck: photo, pin, name, done. The quick-add form must be dead simple.
1. **Idaho Falls is home base, but the tool scales.** The same pipeline works for Boise, Pocatello, Twin Falls, and Utah markets. The city/state fields and map views support multi-market operation.
1. **Proposals should auto-fill from project data.** When generating a proposal, pull the project name, address, GC name, contact, sqft, building type, and calculated pricing into the PDF automatically. Francisco should only need to review and tweak, not start from scratch.
1. **Track win rates and pricing data.** Over time, the system will reveal which building types are most profitable, which GCs are worth pursuing, and whether Imperial is pricing too high or too low. The data from won/lost bids is valuable.
1. **Protect all admin routes** with authentication.
